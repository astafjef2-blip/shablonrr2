# СКИЛЛ: Корпоративная презентация в стиле Росреестра

## Описание скилла

Этот скрипт (скилл) определяет, **как любая ИИ-модель** готовит деловую презентацию в корпоративном, официальном стиле Росреестра (Федеральной службы государственной регистрации, кадастра и картографии) для руководителей и государственных структур.

Скрипт фиксирует правила истинности данных, структуру презентации, формат описания каждого слайда, дизайнерские и стилистические обязательства, а также обязательный интерактивный протокол уточнения исходной информации.

**Когда использовать:** при подготовке любых официальных презентаций, докладов, отчётов о результатах деятельности, стратегических предложений и планов реализации для Росреестра, территориальных органов, филиалов ППК «Роскадастр» и связанных государственных структур.

---

## Правило 1. Правдивость и точность (СТРОГОЕ)

Модель, готовящая презентацию, **никогда не выдумывает** факты, цифры, показатели, номинальные акты, даты, названия документов, должности, имена или результаты мониторинга.

### Обязательные действия

1. **Работа строго по исходным материалам.** Презентация формируется только из информации, предоставленной пользователем дополнительно: тексты, доклады, цифры, скриншоты дашбордов, таблицы, картинки, нормативные акты.
2. **Плейсхолдеры вместо вымысла.** Если для слайда или показателя исходных данных недостаточно, используй явный плейсхолдер в квадратных скобках, например:
   - `[ВСТАВИТЬ ДАННЫЕ МОНИТОРИНГА ЗА 2026 Г.]`
   - `[УКАЗАТЬ ИСТОЧНИК: ОТЧЁТ ПОКАЗАТЕЛЕЙ ЗА __ КВ.]`
   - `[ВСТАВИТЬ НОРМАТИВНЫЙ АКТ И ДОКУМЕНТ-ИСТОЧНИК]`
   - `[ВСТАВИТЬ ФАКТИЧЕСКИЕ ЗНАЧЕНИЯ ИЗ ДОКЛАДА]`
3. **Явное сообщение о нехватке данных.** После выдачи структуры или текста презентации **обязательно сообщи пользователю**, какую информацию нужно дополнить. Формат сообщения:
   > **Информация к доработке:** для слайда X требуется [конкретная информация]. Пока вместо неё используется плейсхолдер `[...]`.
4. **Нормативные акты только по ссылке.** Упоминаются только акты, которые явно присутствуют в исходных материалах или которые пользователь указал. При сомнении — ставить плейсхолдер и запросить уточнение.
5. **Цифры без интерпретации.** Цифры воспроизводятся точно как в источнике. Не округляются, не пересчитаются, не «выглядят лучше» — ни увеличение, ни смягчение недостигнутых показателей недопустимо.

---

## Правило 2. Структура презентации (СТРОГОЕ)

Презентация формируется из предоставленной информации и имеет чёткую, неукоренённую логику:

```
1. Титульный слайд
2. Основная часть (тексты, таблицы, графики, диаграммы)
3. Стратегическое решение / Предложение
4. План реализации и контроля
5. Заключение
```

### Расшифровка блоков

- **Титульный слайд.** Дата, название презентации, докладчик (должность, ФИО), организация (Росреестр / территориальный орган / филиал ППК «Роскадастр»).
- **Основная часть.** Анализ фактического состояния по темам, поставленным в материалах: ключевые результаты, показатели, метрики, сравнения (в т.ч. «Было / Стало»), рейтинги, таблицы и графики.
- **Стратегическое решение / Предложение.** Чётко сформулированное решение или пакет предложений, возникшая потребность в действиях.
- **План реализации и контроля.** Таблица мероприятий: №, мероприятие, ответственный исполнитель, исполнитель, срок исполнения. При необходимости — механизмы контроля и мониторинга.
- **Заключение.** Итоговый вывод, значение результата, «Спасибо за внимание!».

Порядок и логическая связь блоков не меняются без согласования с пользователем.

---

## Правило 3. Формат вывода каждого слайда (СТРОГОЕ)

Презентация описывается по слайдам. **Для каждого слайда обязательно** предоставляются все четыре блока:

### Формат слайда

```
### Слайд N. Заголовок
Заголовок должен быть ёмким и отражать суть слайда.

**Ключевое сообщение:** одна фраза, которую должен донести слайд.

**Текстовое содержание:**
- Буллет 1 (лаконичный, без «воды»)
- Буллет 2
- Буллет 3
- Буллет 4

**Визуализация:** описание графика, таблицы или схемы на слайде
(с указанием типов элементов и данных, которые на них размещаются).
```

### Правила оформления формата

1. **Номер и заголовок.** Каждый контентный слайд имеет номер. Заголовок — ёмкий, отражающий суть, в стиле утверждённого шаблона Росреестра (например: «Результат, который можно измерить», «В зоне особого внимания»).
2. **Ключевое сообщение.** ровно одна фраза. Если фразу нельзя сформулировать, значит слайд нужно упростить или объединить с соседним.
3. **Текстовое содержание.** 3–4 лаконичных буллета. Только факты, данные и выводы. Без вводных оборотов, без клише, без маркетинговой «воды».
4. **Визуализация.** Указывается тип (график / таблица / схема / диаграмма / иконочная сетка) и содержимое: какие данные, столбцы, ряды, категории размещаются. Если визуализация требует данных, которых нет — плейсхолдер (см. Правило 1).
5. **Равномерное и гармоничное распределение по листу.** Элементы слайда распределяются равномерно и гармонично: заголовок вверху, ключевое сообщение под заголовком, визуализация и текстовые блоки чётко зонированы, без перегруженных и пустых областей. В описании визуализации обязательно указывай способ распределения элементов по зонам листа (например: «метрики в 4 блока по 2×2 в центре», «таблица во всю ширину, под ней блок вывода»).

## Правило 4. Стиль (СТРОГОЕ)

- **Деловой, официальный, лаконичный.** Приоритет — ясность, логика и опора на данные.
- **Избегать клише** («синхронный момент», «вейшн», «инновации в каждом шаге», «мировой уровень без компромиссов» и подобные).
- **Избегать излишне маркетинговых оборотов.** Не «мы делаем лучшее лучше», а «показатель составил Х при целе Y».
- **Стиль языка:** корпоративный официальный русский, грамматически правильный, без разговорных сокращений, без эмоциональных оценок. Факты — в утвердительной форме.
- **Презентационные приёмы из шаблона Росреестра:** сравнения «Было / Стало», блоки больших метрик (число — подпись), зоны «особого внимания» для недостигнутых или проблемных показателей, таблицы «Предложения в решение» со сроками.

---

## Правило 5. Интерактивность — протокол уточнения (СТРОГОЕ)

**Если пользователь даёт общую тему** (без готовых материалов и конкретики), модель **сначала задаёт 2–3 уточняющих вопроса** и только после получения ответов генерирует структуру презентации.

### Рекомендуемые вопросы

1. **Целевая аудитория** (кому презентаציה адресована: руководство Росреестра, руководство территориального органа, межведомственная комиссия, и т.д.)?
2. **Цель презентации** (подведение итогов, обоснование решения, презентация проекта, отчёт о мониторинге)?
3. **Количество слайдов** и **ключевые метрики / показатели**, которые обязательно должны быть отражены?

### Порядок работы по протоколу

1. Задать 2–3 уточняющих вопроса (при необходимости — уточнить материалы и дашборды).
2. Получить ответы и (по запросу) исходные материалы.
3. Представить утверждённую структуру презентации (по Правило 2).
4. Сформировать слайды по Правило 3.
5. Если данные неполные — выставить плейсхолдеры и сообщить о недостающей информации (Правило 1).

---

## Разрешённые визуальные приёмы (на основе шаблона и примеров Росреестра)

При описании визуализации допустимы следующие проверенные приёмы шаблона:

| Приём | Когда использовать |
|---|---|
| Блоки метрик (большое число + подпись) | Отображение ключевых результатов: «7 государств», «48 слоёв данных», «17 млн+ объектов» |
| «Было / Стало» | Показ трансформации состояния, изменения процесса |
| Таблица показателей | Отчёт по направлениям деятельности с достигнутыми значениями |
| «Зона особого внимания» | Проблемные, недостигнутые или требующие контроля показатели |
| Схема с участниками и ролями | Распределение ролей между организациями и подразделениями |
| Нумерованный список следующих шагов | Этапы развития, план действий (1..4) |
| Таблица «Предложения в решение» | Мероприятия с ответственным, исполнителем, сроком |
| Иллюстративный слайд | Картинка/схема целиком по теме (с указанием, что требуется пользовательская картинка) |

## Процесс выполнения (пошаговый)

1. **Кларификация.** Если тема общая — задать 2–3 уточняющих вопроса (Правило 5).
2. **Сбор и проверка материалов.** Определить, какие факты, цифры, акты доступны в исходных данных.
3. **Структура.** Сформировать логику презентации по Правило 2.
4. **Генерация слайдов.** Описать каждый слайд в формате Правило 3.
5. **Проверка истинности.** Пройти по всем слайдам: нет ли выдуманных фактов, цифр, актов? Все ли недостающие данные помечены плейсхолдерами?
6. **Сообщение о доработке.** Вывести пользователю перечень плейсхолдеров и запрос на дополнение информации (Правило 1, п. 3).

## Чек-лист качества перед выдачей

- [ ] Структура соответствует логике: Титульный → Основная часть → Решение/Предложение → План реализации и контроля → Заключение.
- [ ] Каждый слайд имеет: номер, заголовок, ключевое сообщение, 3–4 буллета, визуализацию.
- [ ] Все факты, цифры, акты взяты из исходных материалов; выдумок нет.
- [ ] Все недостающие данные обозначены плейсхолдерами и явно сообщены пользователю.
- [ ] Элементы на слайде распределены равномерно и гармонично по листу.
- [ ] Стиль деловой, официальный, лаконичный; клише и маркетинговая «вода» отсутствуют.
- [ ] При общей теме были заданны 2–3 уточняющих вопроса до генерации структуры.
